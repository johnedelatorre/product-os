# /product-os:a11y

Run comprehensive accessibility audit.

## Usage
```
/product-os:a11y --target <prototype.html|url> [--wcag <level>]
```

## Arguments
| Argument | Required | Description |
|----------|----------|-------------|
| `--target` | Yes | The real design: `prototype.html`, a prototype or live URL (full audit), or a Figma link, screenshots or `wireframes.md` (static checks only) |
| `--wcag` | No | WCAG level (default: AA) |

## Reviews the Real Design Only

1. **Needs the actual design:** `prototype.html` or a live URL for the full audit; a Figma link, screenshots or `wireframes.md` for static checks. Without one, the agent stops and asks you for it. It never reviews a described or imagined screen.
2. The report opens with the standard header (`docs/reference/document-format.md`) and §1 **What was reviewed**: files or links, screen IDs (`SCR-###`, prototype `#scr-###`, Figma node IDs), version, review date.
3. Every finding cites the exact screen, element and file line (for example SCR-003 → Retry button, `prototype.html` line 226), with a screenshot or frame link where possible.
4. Anything the agent could not inspect is marked **Not Verified**, not guessed.
5. **Needs a running build:** automated scans (axe-core, pa11y, Lighthouse), keyboard navigation and screen reader checks run only against `prototype.html` in a browser or a live URL. Without one they are reported as Not Verified, with no scan counts.
6. **Needs real colours:** contrast is checked against Figma values or the built UI; on grayscale wireframes it is Not Verified.

## Checks
- WCAG 2.2 AA full checklist
- Automated scans (axe-core, pa11y, Lighthouse)
- Contrast ratio verification
- Keyboard navigation
- Screen reader compatibility
- Focus management
- ARIA usage
- Target size (24×24 CSS px minimum per WCAG 2.2 AA 2.5.8; 44×44px recommended)

## Output
- `accessibility-audit.md` — Full audit report
- `a11y-issues.csv` — Issue log for tracking
- `axe-results.json` — Raw scan data

## Agent
Uses: `accessibility-auditor.md`
